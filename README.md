# 📊 Observability Stack: Prometheus + Grafana + Loki

Проект по системному администрированию: развертывание полноценного стека наблюдаемости (Observability) для серверной инфраструктуры на базе Docker Compose.

## 🎯 Цель проекта
Развернуть изолированную систему мониторинга и логирования, которая собирает метрики (CPU, RAM, диск, сеть), агрегирует системные логи и визуализирует их в единых дашбордах, а также позволяет настраивать алерты для оперативного реагирования на инциденты.

## 🏗️ Архитектура и стек технологий
Проект развернут на виртуальной машине под управлением **Ubuntu Server LTS**. Все компоненты изолированы в Docker-контейнерах и объединены в единую внутреннюю сеть.

*   **Prometheus** — сбор и хранение метрик.
*   **Node Exporter** — агент сбора системных метрик хоста.
*   **Loki** — агрегация и хранение логов.
*   **Promtail** — агент сбора логов из файлов (syslog, auth.log).
*   **Grafana** — визуализация данных (метрики и логи).

## 🔒 Особенности безопасности (Hardening)
При развертывании проекта применены принципы **Zero Trust** и минимизации поверхности атаки:
*   **Изоляция сети:** Порты Prometheus (9090), Loki (3100) и Alertmanager (9093) **не публикуются** на хост-систему. Они доступны только внутри Docker-сети.
*   **Доступ к веб-интерфейсу:** Порт Grafana привязан к `127.0.0.1` (доступен только локально). Внешний доступ осуществляется безопасно через SSH-туннель.
*   **Управление секретами:** Пароли (например, для Grafana) хранятся в файле `.env`, который исключен из системы контроля версий с помощью `.gitignore`.
*   **Файервол:** Настроен UFW, открыты только необходимые порты (22/SSH, 80/HTTP, 443/HTTPS).
*   **SSH:** Доступ по ключам Ed25519, вход по паролю и под root отключен.

## 🚀 Инструкция по развертыванию

### Предварительные требования

*   Установленный Docker и Docker Compose.
*   Настроенный файрвол (UFW).
*   Открытые порты: `22` (SSH).

### Шаг 1: Клонирование репозитория

```sh
git clone https://github.com/tet808/observability-stack.git
cd observability-stack
```
### Шаг 2: Настройка переменных окружения

Создайте файл .env на основе шаблона. Задайте пароль для администратора Grafana

```sh
cp .env.example .env
nano .env
```

### Шаг 3: Запуск стека

Запустите контейнеры в фоновом режиме

```sh
docker compose up -d
```
Проверьте, что сервисы работают:

```sh
docker compose ps
```

## 🖥️ Доступ к интерфейсам (SSH-туннели)

Поскольку панели управления скрыты от внешней сети для безопасности, для доступа к ним используется SSH-проброс портов.

**На хосте:**

```sh
ssh -L 3000:localhost:3000 -L 9090:localhost:9090 <user_name>@<IP_СЕРВЕРА>
```

Grafana: `http://localhost:3000` (Логин: admin, пароль из `.env`)

Prometheus: `http://localhost:9090`

## 📂 Структура проекта
```text
.
├── .env.example               # Шаблон переменных окружения
├── .gitignore                 # Исключения для Git
├── docker-compose.yml         # Главный файл конфигурации Docker
├── grafana/
│   └── provisioning/          # Автоматическое подключение источников данных
├── loki/
│   └── loki-config.yaml       # Конфигурация хранения логов
├── prometheus/
│   ├── prometheus.yml         # Конфигурация сбора метрик
│   └── alert_rules.yml        # Правила алертов (CPU, RAM, Disk, Down)
└── promtail/
    └── promtail-config.yaml   # Конфигурация сбора логов с хоста
```
